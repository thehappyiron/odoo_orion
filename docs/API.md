# Local application API

Better Auth owns `/api/auth/*`. The application uses `/api/v1/*`; all application endpoints require a valid HTTP-only session. Mutations also require a same-origin `Origin` header and a JSON body of at most 64 KB. There is no cross-origin API access.

Successful responses are `{ data, meta: { requestId } }`. Errors are `{ error: { code, message, requestId } }`. Money fields are integer paise, dates are `YYYY-MM-DD`, timestamps are UTC, and the currency is INR. Server-controlled totals, ownership, status and audit actors are rejected from ordinary mutation schemas.

Collections return `{items,total,page,pageSize:25}`. Parameters include `page`, `search`, applicable `status`, `from`, `to`, `customer`, and `plan`. Date filters on invoices/dashboard billed amounts use billing dates; payment cash filters use receipt dates. Active subscription counts are as of business today. Staff and customer scope rules are always enforced in the domain service as well as the API.

Subscription lifecycle body: `{action,version,reason,expiry_on?}` where action is `issue|confirm|activate|pause|resume|close|renew`. Invoice body: `{action,reason?}` where action is `confirm|recalculate|cancel|send`. Cancellation and reversals require an explanation. Discount redemption and invoice confirmation share a PostgreSQL transaction.

`POST /api/internal/billing` uses a scheduler bearer secret rather than a user session. `GET /api/health` returns database availability without exposing credentials. The local CLI worker is the default demonstration scheduler.
